# Where the sgi-gr2 crate's constant names come from

The Rust crate `rust/sgi-gr2` in the QEMU `sgi-origami` tree (branch `sgi-origami-indigo-gr2-variants`, commit `a37c7ffe0f86`, "tests/qtest: pin the Express board's register contract") carries 472 named constants and statics in `src/`, tests included (the first count said 471; a recount by a second reader finds 472, and which one the first count missed is not known). This page says, for each prefix family, where a name can be traced to. It covers names only: no value, layout or comment was compared, and a name that matches a source is a possible origin, not proof of derivation. The crate was read, not changed.

Origin classes, as the QEMU pages need them:

- **Shipped developer header**: a name defined in a header the IRIX install discs ship. Citable by header and release.
- **Shipped binary symbol**: a name in a shipped binary's symbol table.
- **Published**: a name in a public document or driver (NetBSD `grtworeg.h` and `grtwo.c` here).
- **Source-only**: a name found only in the IRIX source tree or in the upstream headers `HQ2.h`, `RE3.h` and the rest of the `gr2` repository, which were generated from vendor source ([AGENTS.md](../AGENTS.md)). Not citable from a QEMU page.
- **Crate-own**: found in none of the above.

A bare word that is also an ordinary identifier elsewhere (`DAC`, `FIFO`, `VC1`, `XMAP`, `ALL`, `OPEN`, `MASK`) is not counted as a match.

Moved by the review: ten names are case or prefix variants of shipped or published names and so citable, not crate-own: `BDVERS`, `CLOCK`, `HQUCODE`, `SHRAM` and `XMAPALL` are members of `struct gr2_hw`, `FIN1`, `FIN2` and `FIN3` are members of `struct hq2` (also NetBSD `HQ2_FIN1` to `HQ2_FIN3`), all in `sys/gr2hw.h`, and `SYSCTL_CURSOR` and `SYSCTL_CURSOR_DISPLAY` are NetBSD's `VC1_SYSCTL_CURSOR` and `VC1_SYSCTL_CURSOR_DISPLAY` with the prefix cut. Eighteen names are source-only, not crate-own: `USEV`, `LOADV` and `ITOF` (the diagnostic's GE7 token flags, with the same values `0x200`, `0x400` and `0x4000`), `GL_FINISH`, `GL_FLUSH`, `GL_SWAP_BUFFERS` and `VR_OUTSIDE` (upstream `HQ2_GL_*` names, same values), `SHRAM_CX_OWNER`, `SHRAM_CX_SIZE_MAIN` and `SHRAM_CX_SIZE_EXT` (upstream `GE7_SHRAM_CX_*`), `X_ADJ` and `Y_ADJ` (upstream `VC1.h`, same values 250 and 35), `T_BLEND_FACTOR`, `T_BLEND_MODE`, `VC1_CMD1`, and, as weak matches, `IR` (RE3.h's instruction register, a different meaning) and the two `FIFO_DEPTH` names. Four `T_IRIS_*` names moved from shipped symbol to crate-own.

Generic exception: `BUS_BUSY` is the iris core's own bus-status name, used by every iris device, not a name the GR2 crate took from any source. It is left out of both lists, and an audit should not flag it.

## Reading it

Tally of the 472 names: 23 are shipped developer header names by exact match and 33 more (`HQ_`, `VC1_`, `XMAP_`) are upper-cased member names of structs in `sys/gr2hw.h`; 10 more are case or prefix variants of shipped or published names (listed above); 19 are shipped binary symbols (IrisGL function names); 1 is a published name by exact match (`HQ2_MYSTERY`; five `VC1_` names overlap with NetBSD); 195 are source-only; 191 are crate-own, including 34 constants with no prefix. A QEMU page can cite the shipped, binary-symbol and published classes. The source-only families, `HQ2_2D_*`, `REG_*`, `RWMODE_*`, `IR_*`, `GE_CX_*` and 66 of the `T_` names, name registers and tokens that only the vendor-derived headers or the IRIX source tree name; a QEMU manual page must not cite them, and the crate's use of them is the question the owner of the crate has to decide. For the token names there is a way out that rests on shipped evidence: the GL cores' own function names (`__glexpim_RasterPos2f`, `PassLineStipple`, `LoadLightPath` and the others in [pipeline.md](../platforms/express/pipeline.md)) name every token the GL cores send, and the IrisGL symbols name 19 of the `T_IRIS_*` ones.

Method, for repeating it: an identifier scan of each corpus (upper-case words for the headers and sources, the printable strings of each binary), then the exact-name, member-name and suffix tests described in each row. No tool is committed for it.
