# HQ2 slot table: operand words and GE7 start per release

Generated by [tools/hq2-slots.py](../../tools/hq2-slots.py) from the `hq2.bin` of IRIX 5.3, 6.2 and 6.5 (hashes in [binaries.md](../../references/binaries.md)); regenerate with

    tools/hq2-slots.py table 5.3=IMG 6.2=IMG 6.5=IMG

Each row is a FIFO slot (bits 10:2 of the store address) that has a first-level HQ2 word in at least one of the images. *Words* is the number of operand reads on the slot's walk, at least one, by the rule in [microcode.md](microcode.md#operand-counts-from-the-slot-code); a `*` marks a walk that crosses a conditional branch (the count then holds only for the fall-through path). *GE7* is the start address the walk reaches, or `ends` when the walk reaches the end word of a routine first (the HQ2 keeps the command to itself, or the GE7 start lies behind another entry). `-` means the image has no first-level word for the slot. Slot numbering follows [pipeline.md](pipeline.md#fifo-token-encoding); the host senders of each slot are in the GL token table there. Inferred throughout: the counts are a reading of the HQ2 words, not a decoded instruction set. Values only, no listing.

## Publishing it as generated data

Asked whether this table can live in `generated/rust` beside the register maps. Yes in principle, and not yet in practice:

- **What may be published.** Slot numbers, whether a first-level HQ2 word exists, and the GE7 routine a walk reaches are read from the shipped images and are **established** for the walk (the rule in [microcode.md](microcode.md#operand-counts-from-the-slot-code) is applied to every word). The *words* column is **inferred**: it agrees exactly with what the 6.5 GL core stores for 64 of the 103 slots checked, with a multiple for 23 and with neither for 16, and
  it depends on address bits 15:12 for the vertex, colour and index families, so a slot number alone is the wrong key for those. Numbers derived from the binaries are the kind of fact this repository already commits, and the table names no vendor symbol; the nine console token names would be NetBSD's, the rest would stay numbers (the X tokens are unnamed).
- **How.** `defs-gen` writes only registers, words and constants, and `defs-check` fails when `generated/` holds a file it did not write, so a side table cannot be dropped there by hand. A 426-slot, three-release table fits as about 2500 constants (one per slot, release and column), each with a grade, which is
  workable but not a table. The clean route is a table kind in `retools/tools/defs`, a shared-tooling change with its own review, so it was not made here.
- **What blocks regenerating it from this checkout.** The 5.3 and 6.2 `hq2.bin` images are not in the roots a fresh clone links (only the 6.5 image is), so `tools/hq2-slots.py table` can be re-run for one release; the three-release table above was produced when all three were held.
